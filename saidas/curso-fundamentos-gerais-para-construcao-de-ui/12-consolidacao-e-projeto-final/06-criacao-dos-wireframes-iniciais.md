## Criação dos wireframes iniciais

Ao iniciar um projeto de UI/UX, a criação dos wireframes é o passo fundamental para transformar ideias e pesquisas em uma estrutura visual tangível. Eles são esboços simples que representam a arquitetura da interface, focando na disposição dos elementos, hierarquia da informação e navegação, sem se preocupar com detalhes visuais ou interativos. Criar wireframes iniciais permite validar rapidamente conceitos, facilitar a comunicação com equipes e identificar problemas estruturais antes de avançar para protótipos mais elaborados.

### Por que wireframes de baixa ou média fidelidade?

Wireframes de baixa fidelidade são representações esquemáticas, normalmente em preto e branco ou tons de cinza, usando formas simples para indicar botões, campos de texto, imagens e menus. Eles evitam distrações visuais, permitindo que o foco seja na funcionalidade e usabilidade. Wireframes de média fidelidade já introduzem algum detalhamento, como tipografia básica, ícones simplificados ou alinhamentos mais precisos, mas continuam sem cores ou elementos gráficos complexos.

Esses níveis de fidelidade são adequados para a fase inicial do projeto porque:

- Permitem iterações rápidas, com mudanças simples e baratas.
- Facilitam a discussão sobre fluxo e estrutura, não estética.
- Permitem incorporar feedbacks iniciais de usuários e stakeholders.
- Evitam que o time se prenda a detalhes visuais prematuramente.

### Preparação para a criação

Antes de começar a desenhar, é importante reunir as informações essenciais já trabalhadas:

- **Personas e necessidades dos usuários**: quais problemas o wireframe deve resolver?
- **Mapeamento da jornada do usuário**: quais telas e etapas precisam ser contempladas?
- **Arquitetura de informação**: como o conteúdo e funcionalidades serão organizados?
- **Objetivos do projeto**: o que é prioritário na interface?

Com isso claro, o wireframe serve para materializar essas decisões.

### Escolha da ferramenta

Para wireframes iniciais, o uso de ferramentas simples e ágeis é recomendado. Muitos designers começam com esboços no papel ou quadros brancos, mas para maior organização e compartilhamento, ferramentas digitais gratuitas e acessíveis, como o **Figma** ou **Lunacy**, são excelentes opções. Elas permitem criar wireframes limpos, editar facilmente e, se necessário, avançar para prototipagem posteriormente.

### Passo a passo para criar wireframes iniciais

#### 1. Defina a grade e a estrutura básica

Comece configurando uma grade simples para alinhar os elementos de forma consistente. A grade ajuda a manter o equilíbrio visual e a hierarquia entre os componentes da interface.

Por exemplo, em uma tela web, pode-se usar uma grade de 12 colunas, comum no design responsivo.

#### 2. Esboce o layout principal

Desenhe os blocos que representam as áreas principais da tela: cabeçalho, menu, área de conteúdo, barras laterais, rodapé. Use caixas retangulares vazias para indicar espaços reservados para textos, imagens ou botões.

```plaintext
+-------------------------------------------------+
| Logotipo       | Menu        | Ícone de Perfil  |
+-------------------------------------------------+
| Sidebar       | Conteúdo Principal               |
|               |                                |
|               |                                |
+-------------------------------------------------+
| Rodapé com links e informações                  |
+-------------------------------------------------+
```

Esse esboço inicial já dá uma ideia clara da estrutura, sem necessidade de cores ou imagens reais.

#### 3. Insira os componentes funcionais

Dentro do layout, coloque os elementos que o usuário vai interagir, como:

- Botões (representados por retângulos com texto)
- Campos de formulário (caixas vazias com indicação de label)
- Listas ou tabelas (linhas simples)
- Ícones (simbolizados por formas geométricas simples)

Evite usar ícones reais nesta fase; o foco é na posição e tamanho.

#### 4. Indique a hierarquia visual

Use a variação do tamanho das caixas e disposição para demonstrar o que é mais importante. Por exemplo, títulos maiores ou botões de ação principais em tamanho maior.

Também é útil numerar as telas ou componentes para explicar o fluxo.

#### 5. Documente interações básicas (sem prototipagem)

Ainda que não sejam protótipos interativos, anote as ações esperadas, como “ao clicar aqui, abre o menu” ou “campo obrigatório”. Isso ajuda a preparar o refinamento posterior.

### Exemplo prático

Imagine que você está criando wireframes iniciais para um aplicativo simples de lista de tarefas.

1. **Tela principal**: lista de tarefas exibida em uma coluna, botão flutuante para adicionar nova tarefa no canto inferior direito.

2. **Tela de criação de tarefa**: campo para título, campo para descrição, botão salvar e botão cancelar.

Veja abaixo um wireframe de baixa fidelidade para a tela principal, feito em texto para visualização.

```plaintext
+-------------------------------------------------+
| Tarefas                                         |
+-------------------------------------------------+
| [ ] Comprar leite                               |
| [ ] Estudar UI/UX                              |
| [ ] Enviar e-mail                              |
+-------------------------------------------------+
| (+)                                           |
+-------------------------------------------------+
```

Neste exemplo, o "(+)" representa o botão de adicionar tarefa, posicionado estrategicamente para fácil acesso.

### Erro comum: wireframe muito detalhado ou com elementos visuais

Um erro frequente é tentar inserir cores, imagens reais, fontes específicas e interatividade logo no primeiro wireframe. Isso pode gerar confusão e atrasar o processo, pois a equipe e usuários acabam focando em detalhes visuais que ainda não estão definidos, desviando a atenção da estrutura e funcionalidade.

Exemplo de erro:

- Criar um wireframe colorido com imagens reais resulta em:

  - Maior tempo de produção.
  - Feedbacks focados em estética e não em usabilidade.
  - Dificuldade para alterar estrutura posteriormente.

### Como corrigir

Concentre-se nas formas básicas e disposição dos elementos usando caixas e linhas simples. Reserve a aplicação de estilo visual e interatividade para fases posteriores de prototipagem.

### Exercício prático

Escolha um aplicativo ou site simples, como um gerenciador de tarefas, um blog ou uma loja virtual pequena, e crie um wireframe inicial para a página principal e uma tela secundária (ex: página de produto ou criação de tarefa).

- Use papel e caneta, ou uma ferramenta digital como o Figma.
- Defina a estrutura básica com cabeçalho, corpo e rodapé.
- Indique os principais componentes funcionais: menus, botões, campos.
- Não use cores, imagens ou fontes estilizadas.
- Anote as interações esperadas para cada elemento.

### Solução comentada

Veja um exemplo simplificado para a página principal de um blog:

```plaintext
+-------------------------------------------------+
| [Logo]           Blog                             |
+-------------------------------------------------+
| Menu: Home | Categorias | Sobre                  |
+-------------------------------------------------+
| [Imagem destaque]                                |
| Título do post em destaque                       |
| Resumo do post                                   |
+-------------------------------------------------+
| Lista de posts:                                  |
| 1. Título do post 1                              |
| 2. Título do post 2                              |
| 3. Título do post 3                              |
+-------------------------------------------------+
| Rodapé com contatos e redes sociais              |
+-------------------------------------------------+
```

- A estrutura está clara: cabeçalho, menu, conteúdo principal e rodapé.
- Os elementos são representados por caixas e textos simples.
- Não há cores nem imagens reais, apenas indicação onde elas estarão.
- O foco está na posição e hierarquia da informação.

Esse wireframe pode ser criado rapidamente, apresentado para feedback e ajustado antes de avançar para protótipos mais detalhados.

---

Criar wireframes iniciais eficazes exige disciplina para manter a simplicidade e foco na estrutura, facilitando o entendimento da interface e a comunicação com o time e usuários. Essa etapa é a base para o sucesso do projeto e para as fases seguintes do processo de design.
