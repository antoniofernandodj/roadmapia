# Introdução ao Design de UI/UX

Quem desenvolve software convive com uma frustração recorrente e difícil de nomear: o sistema funciona, passa nos testes, atende ao que foi pedido — e as pessoas que o usam reclamam, erram, pedem treinamento, ou simplesmente encontram um jeito de contornar aquilo que você construiu. A distância entre "funciona" e "funciona para alguém" é o território deste curso, e este capítulo é onde essa distância ganha nome, vocabulário e método.

O problema que ele resolve é de orientação. Vindo do desenvolvimento, você já sabe construir; o que falta é saber decidir **o que** construir e **por quê**, a partir de quem vai usar. Sem essa base, é comum confundir UI com UX, tratar design como acabamento visual aplicado no fim, ou avaliar interfaces por gosto — e nenhuma dessas leituras sobrevive ao contato com um usuário real.

Este capítulo abre a obra porque tudo o que vem depois depende dele. Não dá para estudar psicologia cognitiva aplicada sem saber o que se está tentando otimizar; não dá para conduzir pesquisa com usuários sem entender por que a opinião de quem constrói não substitui a observação de quem usa; não dá para montar um portfólio sem saber o que a área valoriza. Aqui você recebe o mapa antes de percorrer o terreno.

A sequência dos trechos segue uma lógica de aproximação sucessiva. Você começa pela distinção fundamental entre interface e experiência, e vê como o campo chegou até aqui — da linha de comando às interfaces gráficas, das telas de desktop à multiplicidade de dispositivos atual. Em seguida, conhece os papéis profissionais envolvidos e a razão de o design centrado no usuário existir como abordagem, com o design thinking e as etapas do processo como o método que a operacionaliza.

Depois vem o vocabulário de trabalho: as diferenças entre projetar para web, mobile e desktop; a terminologia básica que você vai encontrar em qualquer conversa da área; os entregáveis que um profissional produz — personas, wireframes, protótipos, mapas de jornada — e as ferramentas em que eles são feitos, Figma e Lunacy. Com isso, você deixa de ser espectador das conversas de design e passa a participar delas.

O capítulo então conecta o trabalho ao resultado: como decisões de interface afetam o sucesso do produto, o que usabilidade significa de forma verificável, e como a comunicação entre desenvolvimento e design determina quanto do que é projetado chega ao usuário. Fecha tratando do percurso profissional — o papel do portfólio, a ética envolvida em projetar coisas que influenciam comportamento, as tendências atuais, os desafios específicos de quem faz essa transição — e entrega um glossário e uma trilha de estudo contínuo.

Ao concluir este capítulo, você saberá distinguir com precisão UI de UX, nomear as etapas de um processo de design e o que se produz em cada uma, reconhecer os principais entregáveis quando os encontrar, conversar com designers usando o mesmo vocabulário, avaliar uma interface por critérios em vez de gosto, e entender o que o mercado espera de alguém que está entrando na área. É a base sobre a qual os onze capítulos seguintes constroem competência prática.
